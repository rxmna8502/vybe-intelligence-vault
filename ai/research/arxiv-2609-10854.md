# No-Box Vulnerability Analysis: Description-only Detection of Indirect Prompt Injection Vulnerabilities in MCP Servers

## Summary

arXiv:2609.10854v3 Announce Type: replace-cross 
Abstract: When auditing remotely hosted services or commercially gated software for vulnerabilities, third-party analysts may lack both direct system access and the ability to interact with the running system. We call this a no-box setting, in which analysts have access only to functionality metadata that may describe the intended inputs, behaviors, and outputs of the system. Such descriptions constrain the possible implementations of a system, enabling analysts to hypothesize potential implementations and their underlying vulnerabilities. These hypotheses can subsequently guide validation when system access becomes available. To demonstrate the feasibility of conducting vulnerability analysis under no-box setting, we implemented MCPSEC, a prototype that audits Model Context Protocol (MCP) servers for indirect prompt injection vulnerabilities using only the tool metadata exposed at server registration time. Flagging vulnerable tools, MCPSEC produces hypothesized vulnerabilities and attack scenarios for later validation. We evaluated MCPSEC on 20 widely deployed MCP servers comprising 177 tools, among which human evaluators confirmed 95 as vulnerable. Using only tool metadata, MCPSEC successfully identified 94 of these confirmed vulnerable tools (98.9% recall), compared to 81 (85.3% recall) identified by an agentic baseline. Overall, we operationalize and evaluate no-box vulnerability analysis and demonstrate its practical feasibility in realistic systems.
