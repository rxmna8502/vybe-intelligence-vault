# A Threshold Model of Fault Propagation in AI-Native Software Ecosystems

## Summary

arXiv:2604.19827v2 Announce Type: replace-cross 
Abstract: When many coding agents work in one repository at once, software engineers are left to judge a collective through its parts. Review examines one change at a time, yet a change can incorporate a fault introduced by another, and repairing the originating change then no longer repairs the repository. To keep human judgment at the centre of agentic software development, we need models of what agents do together. This paper joins complexity theory with software evolution to build one. We model how a fault spreads among open changes as a branching process over contention, the relation between two changes that are open at the same time and modify a common file. As with the reproduction number of an epidemic, spread sustains itself once each faulty change passes the fault, on average, to more than one other. Each repository has a reference threshold, the crossing probability per contention link above which spread would sustain itself in a random graph with the repository's contention degrees. We reconstructed contention among 33,105 agent-authored pull requests in 2,731 repositories. Thirteen repositories with reference thresholds below 5% contained 42.5% of the changes. There, a fault that crossed one contention link in twenty would sustain spread under the model. The structural conditions for propagation are in place where much agent-authored work happens. Reviewing each change separately cannot reveal these conditions. Engineers also need to know where concurrent work exposes a repository to spreading faults, which they can compute from records they already keep.
